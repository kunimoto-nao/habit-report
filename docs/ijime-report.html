いちばんつらかった場面

定例教育委員会の直前。各学校から上がってきた件数を手で足し、前回と同じ体裁の集計表を作り、その数字を委員の前で読む原稿に書き直す。表と原稿を、毎回ゼロから作っていた。

ツールの前

  • 全校分を手集計する
  • 集計表をゼロから組む
  • 読み原稿もゼロから書く
  • 作業が定例直前に集中する
→

ツールの後

  • 表データを入れる
  • 前回と同じ体裁の表が出る
  • その数字から読み原稿も出る
  • 直前のゼロ作成がなくなる

④ 工夫したポイントと苦戦したポイント

表の体裁を固定して一気に出す。合わない合計は、読み込みを直して合わせた

工夫｜前回と同じ体裁で、表と原稿を一気に出す

集計表は、前回の定例と同じ体裁になるように自動作成する。その数字から、読み原稿までセットで出す。手作業の核心だった「ゼロから作る」を、入口の表データに置き換えた。

苦戦｜学校の件数を足しても、市全体と一致しない

学校ごとの件数を足しても、市全体の合計と合わなかった。定例資料は、合計が1件でも違うと使えない。原因は「足し算の考え方」より先に、データを正しく読み込めていない側にあった。

気づき：AIと何度もやり取りし、正しく読み込むようツールの修正を重ねて、合計が合うようにした。
学校計 ≠ 市計 → AIに状況を渡す → 読み込みを修正 → 合計が一致する
↓ 受けて、仲間がやること

この制作の起点は「AIで何か作る」ではなく、「定例の直前に、自分が毎回やっている作業」だった。入口を表データに固定し、出口を「前回と同じ体裁の成果物」にすると、現場で使えるものになる。合わない数字は、生成AIに丸投げせず、読み込みを一つずつ直す。
